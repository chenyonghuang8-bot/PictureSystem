# Phase 7A — Trash and durable purge foundation

Status: Phase 7A complete; this commit is the foundation checkpoint. Phase 7 is not complete or production ready.

The approved Phase 7 design keeps Trash as a canonical media lifecycle state. Migration `0007_phase_07_trash.sql` adds lifecycle revision, Trash timestamps and request identity to `media_items`; a historical `RETIRED` upload receipt; `PURGING` storage state; and dedicated `purge_intents`, `purge_files`, and `audit_logs`. A 30 × 24-hour retention relation is checked by MySQL. Intent uniqueness is `(family_id, media_id, lifecycle_revision)`, so manual and scheduled requests cannot create separate intents for one lifecycle. Historical IDs in intents and audit logs do not reference deletable media or storage rows. `RETIRED` receipts retain the historical storage ID without a live storage FK.

The exact 0006 readiness manifest is frozen in `packages/db/drizzle/phase6_readiness.json`. The ordinary readiness comparator expects 0007 after it is applied. The Phase 7 preflight checks the exact seven-row journal and 0006 physical schema read-only before any future `--apply`. MySQL DDL is not transactional: if future application partially fails, stop, inspect the live schema and journal, and require an explicit forward-repair decision. This 7A task does **not** apply 0007.

`PurgeIntentRepository` and `AuditRepository` provide internal database primitives only. Lease mutation uses server time, worker identity, monotonically increasing epoch, bounded expiry, and fenced updates; ambiguous COMMIT is not replayed. No route, worker execution, receipt retirement, or file deletion is enabled.

The native `.coord/v1` foundation derives per-content lock identity from the validated root device/inode and marker, family ID, SHA-256, and byte size. Lock files are stable, private, ACL-checked, opened with `openat`/`O_NOFOLLOW`/`O_CLOEXEC`, and revalidated against the named inode after acquiring nonblocking `flock`. Pure readers can hold R-shared without acquiring global writer ownership or L; lifecycle producers acquire L before R, and R-exclusive requires L-exclusive. The intended producer order remains writer ownership → upload mutex if applicable → L → R → hash mutex if applicable → CapacityGate → short DB coordination. There is no S-to-X upgrade.

Before a new cross-process FD handoff, native code durably records supervisor identity and then receiver PID plus macOS `proc_pidinfo(PROC_PIDTBSDINFO)` start time, under a `kern.bootsessionuuid` boot identity. The new send entry point checks durable registration and Unix socket peer PID before `SCM_RIGHTS`, and closes the parent Original FD on success. Exact-child `waitpid` settlement marks the record settled. Unresolved live or uncertain records block effective R-exclusive admission; dead process or prior-boot records can be recovered only when native identity checks are decisive. Existing Phase 6 handoff call sites have **not** been switched to this entry point; that wiring and the full original/derived path fences belong to 7B before any purge capability is enabled.

Tests use synthetic roots and files. Native handoff tests need macOS boot/process queries, which the sandbox blocks; run them with the approved read-only sandbox escalation. Repository runtime tests that require 0007 must wait until migration application after independent review. No Production database or media was accessed.
