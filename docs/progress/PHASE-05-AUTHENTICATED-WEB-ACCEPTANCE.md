# Phase 5 Authenticated Web UI Acceptance

## Result

`AUTHENTICATED_UI_ACCEPTANCE: PASS`

The original fail-closed run found that the Web family loader requested the
stale `/api/v1/me` path. Remediation B changed only that request to the existing
`/api/v1/auth/me` contract. A behavioral regression test now fixes the endpoint
and strict response-schema expectation. The complete HTTPS browser acceptance
and full quality gate subsequently passed.

## HTTPS test mechanism

- A dedicated `playwright.web.config.ts` starts the API and Next Web server on
  isolated test ports.
- The browser-facing Next server uses an ephemeral, repository-external
  self-signed certificate generated by the fixed macOS OpenSSL executable.
- Playwright ignores certificate trust errors only for this local test server.
- The API remains internal HTTP behind the existing Next rewrite.
- Production TLS, cookie, and trusted-Origin behavior is unchanged.

## Synthetic authentication

- The test created one uniquely named synthetic DEV user, family, membership,
  and family-visible album.
- The password was hashed with the real password engine.
- Login used `POST /api/v1/auth/login` with the trusted HTTPS Origin.
- Chromium received `__Host-family_session` with Secure, HttpOnly, Path `/`,
  and SameSite Lax attributes.
- Browser JavaScript could not read the session cookie.
- No raw session or share token was written to this document or test output.

## Route correction and regression

- `apps/web/lib/gallery-server.ts :: loadFamily()` now requests
  `/api/v1/auth/me`.
- The backend route and `meResponseSchema` are unchanged.
- `apps/web/lib/gallery-server.test.ts` proves the exact endpoint, first-family
  selection, display-name mapping, and strict rejection of unexpected response
  fields.
- No backend alias, authentication bypass, or response-shape change was added.

## Fixture and cleanup

- Two synthetic media rows and valid WebP thumbnail/preview fixtures were
  prepared in a temporary StorageRoot for photo-rich acceptance.
- All DB rows were removed by exact synthetic family/user IDs after each run.
- Residue verification found zero matching users, families, albums, media,
  derived assets, shares, and sessions.
- The temporary media root was removed; filesystem residue is zero.
