# Phase 4D3a-0 — macOS Renderer Startup Sandbox Capability

Status: **synthetic startup capability implemented and validated for the observed macOS DEV build only**. This is not a renderer, an image-format capability, a DerivedStore, a production isolation approval, or completion of D3a-1/D3a-2. The startup-only amendment in [Phase 4D3a review](PHASE-04D3A-STARTUP-ISOLATION-REVIEW.md) remains authoritative.

## Fixed startup architecture

`OriginalReader.withVerifiedOriginal` provides a single-use, marker-bound, full-hash-verified read-only handle. The D3a-0 qualification adapter consumes it into the fixed native `image_renderer_supervisor`; no original path is passed to the child. The supervisor launches only its build-pinned `image_renderer_bootstrap` with `posix_spawn`, `POSIX_SPAWN_CLOEXEC_DEFAULT`, fixed file actions and `LANG=C`, `LC_ALL=C`. The tiny C bootstrap applies one embedded final sandbox with `sandbox_init(profile, 0, ...)`, independently checks `process-exec` and `process-fork` denial, emits `PS_RENDER_READY_V1\n`, then `dlopen`s one fixed synthetic C module in the same process. No second exec, ImageIO, CoreGraphics, Objective-C, libwebp or real image renderer is involved.

Pre-sandbox bootstrap code performs only fixed argv/FD access-mode/type checks, activation and error handling. It does not read/mmap/pread FD3 or load a module. The synthetic module's constructor reports `MODULE_LOADED`; after `pread(3)` it reports `FIRST_FD3_READ`. The supervisor accepts exactly `SANDBOX_ACTIVATED → MODULE_LOADED → FIRST_FD3_READ` in its bounded internal test event channel and the exact control output `PS_RENDER_READY_V1\n{"status":"ok"}\n`. Early-read fault injection is rejected, proving the event guard detects a deliberate ordering violation. Activation failure has no READY or module/read events. The test events are not a production renderer protocol or proof against a malicious replacement of the trusted bootstrap.

Fixed FD map in this slice: FD0 `/dev/null` read-only; FD1 bounded control pipe; FD2 bounded, fixed test-event pipe; FD3 verified seekable read-only synthetic original. Supervisor FD4 is owner-liveness only and is **not** inherited by the bootstrap. Binary FD4 is reserved for D3a-2 and is not implemented. The parent cannot supply executable, module, sandbox profile, argv, FD numbers or env. The synthetic fault executables are separate, build-fixed test artifacts; no fault selector is available to the normal startup adapter.

The final profile is a literal compiled into bootstrap, deny-default and without an outer `sandbox-exec`. For this pure-C synthetic module it allows inherited FD operations, the fixed module and `/dev/null`; it does **not** grant a broad `/System/Library` subtree read. It denies filesystem writes, process fork/exec and network. It does not include MEDIA_ROOT, original filename, HOME, caller paths or an output directory. The custom `sandbox_init` profile API is deprecated/unsupported by the public SDK: it is a tested macOS DEV backend only. Under a pre-existing Codex or `sandbox-exec` sandbox, activation fails closed; it is never treated as a successful tightening. D3a-2 must separately review any exact sealed-OS reads actually needed by ImageIO, rather than broadening this profile implicitly.

The supervisor checks exact bootstrap and module SHA-256 against build-embedded fingerprints, requires regular single-link files owned by the current UID without group/other write permission, and compares `kern.osversion` to the build-time macOS build. This is accidental-drift protection, not a defense against a hostile same-UID installation rewrite/TOCTOU. The production renderer/module/dependency fingerprint must be requalified when D3a-2 exists.

- Bootstrap SHA-256: `1242fe0357864787ee3d73de94db27101a4e9874dc9880113a4dbd758f39784f`.

- `otool -L`: bootstrap depends only on `/usr/lib/libSystem.B.dylib`; synthetic module depends only on libSystem. Bootstrap has no `LC_RPATH` or `__mod_init_func`; there are no renderer frameworks, plugins or user-controlled dylib dependencies.
- The approved unsandboxed macOS DEV launch completed READY and synthetic module under the final policy. The Codex outer sandbox and explicit pre-sandboxed launch both failed closed without READY. This distinction is expected and must not be hidden with an unsandboxed fallback.
- The synthetic module independently checks fork, `/usr/bin/true` execve, bootstrap self-exec and posix_spawn return permission denial; it checks existing synthetic sentinel read and writable open, root browse, IPv4 and IPv6 connect, UDP send, mDNSResponder mach-lookup denial plus failed resolver lookup, FD3 read and write/pwrite/truncate/chmod denial, and clean env. A non-permission failure of fork/exec/network/path checks does not count as success.
- Startup tests cover activation failure, missing/bad/duplicate READY, crash, pre-READY timeout, deliberate early FD3 read, fingerprint drift, poisoned parent env, owner-liveness loss and actual owner-process exit. Failure returns no accepted control result. Before/after synthetic original snapshots compare bytes, SHA-256, inode, mode and mtime.
- The renderer executable is never linked to ImageIO/CoreGraphics/libwebp in this slice. No image format is enabled; HEIC and RAW/DNG remain disabled.
- Targeted regression: 13 test files / 150 tests passed / 0 skipped across D3a-0, D0/D1/D2, affected Phase 3, Phase 4A/B/C and migration-readiness. After tightening the synthetic profile, the two D3a-0/OriginalReader files passed again (20/20); no legacy launcher code changed. Workspace lint and typecheck passed; changed-file formatting passed. Repository-wide `format:check` still reports the untouched `packages/db/drizzle/meta/_journal.json` and `0003_snapshot.json`; this D3a-0 change does not rewrite migration metadata. DEV synthetic Phase 4B/C/D2 family/user marker counts and startup temporary-directory count were zero.

## Scope and remaining gates

The D3a-0 capability is test-only. It does not publish a binary image output, touch DB/media/job state, accept a real image, or make an HTTP surface. No schema or migration changed. Native build outputs remain Git-ignored. The tracked denied-secret fixture is a harmless sentinel, not a credential.

D3a-1 still owns exhaustive high-FD (>1023) inheritance testing, complete FD0–5/binary map, process-group lifecycle/post-reap signaling hardening, and full renderer liveness/resource containment. D3a-2 still owns fixed ImageIO/CoreGraphics plus pinned libwebp rendering, bounded FD4 data plane, per-format gates, metadata stripping and parent-side output validation. This report must not be used to enable JPEG/PNG/WebP/GIF derivatives or claim production safety.
