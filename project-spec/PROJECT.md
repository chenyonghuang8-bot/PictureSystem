# PROJECT — 家庭相册系统

## 1. 产品目标

构建一个部署在 Mac mini M4 上的私有家庭相册系统，面向约 5 位家庭成员。

它不是公开 SaaS，不开放公开注册。目标是让家人能够安全保存、浏览、整理、评论、收藏、搜索和备份家庭照片与视频，并在 Android App 与 Web 上获得一致、简单、温暖的体验。

核心原则：

> 家庭原始媒体是长期资产。软件可以重装、数据库可以恢复、缩略图可以重建，但原始照片和视频不能因应用错误被修改或损坏。

## 2. 客户端

### Android App
V1 主要移动端。

底部导航：
- 照片
- 相册
- 回忆
- 我的

打开 App 默认进入全家照片时间线。

### iPad
暂不做原生分发，因为当前家庭只有一台 iPad，且 Apple Developer Program 需要付费。
iPad 可使用响应式 Web。

代码架构不排除未来恢复 iOS/iPadOS 客户端。

### Web
普通家庭成员可：
- 浏览
- 搜索
- 上传
- 管理相册
- 收藏
- 查看地图
- 查看回忆
- 评论
- 下载

管理员登录同一 Web 后额外看到“管理后台”。

## 3. 用户与账号

- 不开放公开注册。
- 管理员生成一次性邀请链接和二维码。
- 新成员通过邀请创建账号和密码。
- username 全系统唯一。
- username 做 Unicode NFKC + lowercase 归一化后判断重复。
- 密码至少 8 位。
- 不强制大小写、数字或特殊字符组合。
- 密码必须使用 Argon2id 哈希，禁止明文保存。

角色：
- Super Admin
- Admin
- Member

## 4. 相册权限

相册支持：
- 全家可见
- 指定成员可见
- 指定成员上传
- 指定成员编辑
- 指定成员删除
- 指定成员管理成员
- 创建者作为 Owner

Super Admin 在应用层也必须遵守相册访问权限。

说明：本系统不是端到端加密。Mac mini 的系统管理员理论上仍可读取磁盘原始文件。

## 5. 媒体

支持：
- JPEG
- PNG
- WebP
- GIF
- HEIC
- RAW / DNG
- MP4
- MOV
- HEVC / H.265
- 4K
- HDR

V1 原则：
- 原文件完整保存。
- 不修改原文件。
- 缩略图、预览图、视频封面均为 derived assets。
- RAW 第一阶段优先保存原文件与 EXIF；高质量 RAW 渲染放后续。
- Android Motion Photo / Apple Live Photo V1 只要求不破坏原始数据，完整动态体验后续实现。

## 6. 上传

V1 必须支持：
- 手动选择照片/视频
- 多文件批量上传
- 上传队列
- 单文件进度
- 失败自动重试
- 网络中断后恢复
- 已完成文件不重复上传
- 上传时选择相册
- 上传后再添加相册
- 同一媒体可属于多个相册，但物理原文件只保存一份

建议使用 resumable upload 协议而不是自研大文件分片。

## 7. 去重

V1 做完全相同文件去重：
- 上传期间计算 SHA-256
- 同一家庭内，相同 SHA-256 + size 的原始对象只存一份
- 不跨家庭做内容去重
- 重复上传时复用已有媒体，并新增上传/相册关系，不让时间线出现无意义重复

智能相似图片去重放 V2。

## 8. 时间线

排序规则：
1. 优先 EXIF 拍摄时间
2. 没有拍摄时间时使用上传时间

首页是全家统一照片时间线。

按年月分组。

## 9. 地图

V1：
- 读取 EXIF GPS
- 地图显示照片位置
- marker 聚合
- 点击地区浏览照片
- 国家 / 城市聚合
- 地图服务不得获得原始照片

## 10. 回忆

V1：
- 往年今日
- 一年前的这周

后续：
- 旅行回忆
- 人物成长
- AI 精选
- 自动故事

## 11. 搜索

统一搜索入口。

V1 可检索/过滤：
- 时间
- 上传成员
- 相册
- 收藏
- Tag
- 地点
- 文件名

V2：
- 人物
- 图片语义
- 自然语言组合搜索

## 12. 收藏

两套收藏：
- 用户个人收藏
- 家庭精选

不做 1–5 星评分。

## 13. Tag / 备注 / 评论

V1：
- 用户手动 Tag
- 媒体文字备注
- 家庭成员评论

暂不做点赞系统。

## 14. 删除

普通删除进入回收站。

回收站保留 30 天。

管理员：
- 恢复
- 提前永久删除

定时任务：
- 自动清理超过 30 天的项目

永久删除必须检查存储对象引用，禁止误删仍被引用的原始文件。

## 15. 媒体归属

上传后媒体属于家庭，而不是上传成员个人。

成员被停用/删除后，已上传媒体继续保留。

必须保留 `uploaded_by` 审计信息。

## 16. 批量导入

V1：
- Web 批量导入
- Mac mini 本地目录导入

目录导入时允许管理员选择：
- 只进入家庭照片库
- 每个一级目录自动创建相册
- 手动映射相册

## 17. 下载/导出

V1：
- 原图下载
- 压缩/预览版本下载
- 多选下载
- 相册导出

大量媒体导出可通过后台任务生成 ZIP。

## 18. 通知

只做 App Push。

通知示例：
- 相册邀请
- 系统备份失败
- 磁盘空间不足
- 存储设备掉线
- 新回忆生成

Push 内容不得包含私人照片本体。

## 19. 管理后台

管理员可以查看：
- 家庭成员
- 照片数量
- 视频数量
- 存储使用
- 各成员上传量
- Worker 状态
- 数据库状态
- 最近备份
- 最近完整性检查
- 审计日志
- 回收站
- 系统健康

支持维护模式。

## 20. 部署

Mac mini M4 24×7 运行。

当前：
- 512 GB 内置 SSD 保存媒体

未来：
- 增加 1 TB 外接 SSD
- V1 提供 CLI 存储迁移
- 后台图形化迁移放 V1.1

外接 SSD 掉线：
- 自动切换只读模式
- 禁止上传、删除及会改变媒体的操作
- Push 管理员

## 当前 DEV 环境与进度

MySQL 9.7.2 LTS；`family_album_dev`；`innodb_native_foreign_keys = ON`、`foreign_key_checks = 1`。
Phase 1A migration 已完成，Native FK runtime probe 正确返回 ERROR 1452；Phase 1B 尚未开始。

## 21. 备份

数据库：
- 每小时备份

建议保留：
- 24 个小时备份
- 14 个每日备份
- 8 个每周备份
- 12 个每月备份

媒体：
- 每天备份到独立备份盘

额外灾备：
- 可以将加密后的备份副本同步到 iCloud
- iCloud 不作为工作目录，也不作为唯一备份

## 22. 完整性检查

每个原始对象保存 SHA-256。

每月自动重新计算并校验：
- missing
- corrupt
- hash mismatch

异常时 Push 管理员。

## 23. DEV / PROD

必须隔离：
- 独立数据库
- 独立 secrets
- 独立媒体目录
- 独立端口/网络配置

Codex 默认只操作 DEV。

DEV 禁止使用真实家庭照片。
